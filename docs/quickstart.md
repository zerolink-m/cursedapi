# cursedapi v1.2 — краткая спецификация

Этот файл — короткий путь к совместимому API. Подробности и исключения описаны в документах по ссылкам; при расхождении применяется полная спецификация.

## Минимальный сервер

1. Реализуйте только нужные пути и методы. Наличие CRUD-ресурса **не требует** всех CRUD-операций, bulk, поиска, пагинации или базы данных. Пример минимального сервера: `GET /v1/health`. Формат путей и вложенных ресурсов — в [paths.md](paths.md).
2. Любой JSON-ответ отдавайте в [CursedJSON](objects/envelope.md): `code`, `code_detail`, `error`, `metadata`, `data` присутствуют всегда. Не-JSON ответы допускаются там, где это разрешено [правилами путей](paths.md). Код — строка из трёх цифр, соответствующая HTTP-статусу по [таблице](codes.md).
3. Передавайте `cursed-version: 1.2` в каждом ответе. Если ответ содержит JSON, укажите обычный `Content-Type: application/json`. Правила остальных заголовков — в [headers.md](headers.md).
4. На существующем пути поддерживайте `OPTIONS` с `Allow` и `cursed-supported-functions`. Первый показывает доступные HTTP-методы, второй — включённые функции по методам. Если дополнительных функций нет: `cursed-supported-functions: none`. При запросе запрещённого метода верните HTTP 405, код `096` и `Allow`.
5. Если метод принимает JSON-тело, используйте [Request object](objects/request.md): `data` и необязательный `options`. Детали в [requests.md](requests.md). Для ошибок возвращайте понятный [Error object](objects/error.md); схема и пример ожидаемого запроса необязательны.

Пример минимального ответа:

```http
HTTP/1.1 200 OK
Content-Type: application/json
cursed-version: 1.2
```

```json
{"code":"000","code_detail":"Success.","error":{},"metadata":{},"data":{"status":"ok"}}
```

Пример обнаружения возможностей этого пути:

```http
OPTIONS /v1/health

HTTP/1.1 200 OK
Allow: GET, OPTIONS
cursed-version: 1.2
cursed-supported-functions: none
```

## Когда нужны дополнительные возможности

- Списки, сортировка, простой поиск и пагинация — [query.md](query.md). `search_method` принимает только методы сравнения; простые условия объединяются через AND.
- Логические группы, диапазоны и наборы значений — [filter.md](filter.md). Фильтр выключен по умолчанию; включив его, сервер публикует схему допустимых полей и лимитов.
- Bulk и частичное выполнение — [paths.md](paths.md), [requests.md](requests.md), [objects/bulk.md](objects/bulk.md).
- Схемы запросов и ответов для конкретного метода и вложенного пути — [schema.md](schema.md). Для сервера без продвинутого фильтра публикация схем необязательна.
- Дополнительные заголовки и правила обнаружения возможностей — [headers.md](headers.md).
