# Пути для cursedapi v1.1

Путь всегда имеет однородную структуру. Существует несколько типов объектов.

## 1. CRUD-объект (из БД или другого источника данных)

Пример таблицы:

```
users:
id: int
name: varchar(64)
added_at: int
```

Стандартный набор эндпоинтов:

| Метод | Путь | Действие |
|-------|------|----------|
| GET | `/v1/users` | Получение всех users (с query-параметрами, см. [query.md](query.md)) |
| GET | `/v1/users/{user_id}` | Получение одного users |
| PATCH | `/v1/users/{user_id}` | Изменение одного users |
| POST | `/v1/users` | Создание одного users |
| DELETE | `/v1/users/{user_id}` | Удаление одного users |

Правило: клиент не может задавать идентификатор создаваемого объекта. Путь
любого CRUD POST всегда без ID в конце: `POST /v1/crud_object`. Идентификатор
генерирует сервер. POST с ID в пути - ошибка (код 040, Invalid request).

### 1.1. Bulk-операции (массовые)

| Метод | Путь | Действие |
|-------|------|----------|
| GET | `/v1/users/bulk/{ids}` | Получение нескольких. `ids` - идентификаторы через запятую: `/v1/users/bulk/1,2,5` |
| PATCH | `/v1/users/bulk/{ids}` | Изменение нескольких одним телом ([requests.md](requests.md)) |
| DELETE | `/v1/users/bulk/{ids}` | Удаление нескольких |
| POST | `/v1/users/bulk` | Создание нескольких. Тело - массив объектов ([requests.md](requests.md)) |

Bulk GET успешен тем же кодом, что и обычный список (000). Код при атомарном
отклонении и код при полном провале всех элементов (когда
`partial_allowed=true`) определяет сам сервер в зависимости от ошибки, так
как предсказать её заранее невозможно.

Bulk-операции атомарны по умолчанию: если хотя бы один объект не прошёл - отклоняется вся операция. Частичное выполнение - только с флагом `partial_allowed` (см. [requests.md](requests.md)). Тогда ответ возвращает код `002` / `004` / `008` (partially), а `data` содержит `succeeded` и `failed` (см. [responses.md](responses.md)).

### 1.2. Вложенные ресурсы

Если объект логически принадлежит другому:

```
GET    /v1/users/{user_id}/avatars
GET    /v1/users/{user_id}/avatars/{avatar_id}
POST   /v1/users/{user_id}/avatars
DELETE /v1/users/{user_id}/avatars/{avatar_id}
```

Вложенность больше 2 уровней не рекомендуется - используйте связи через query (`GET /v1/avatars?search_column=user_id&search=5`).

### 1.3. Кастомные эндпоинты (действия над объектом)

Пример:

```
PUT /v1/users/{user_id}/upload-avatar
POST /v1/users/{user_id}/ban
```

Любой метод и любое название функции объекта. Он как псевдообъект: не имеет ограничений в ответе или в запросе. Но если ответ возвращает какие-либо данные и он в JSON - он должен быть в формате CursedJSON.

Бинарные данные и нестандартные Content-Type допустимы только в кастомных
эндпоинтах и virtual-объектах. Спецификация не контролирует формат таких
запросов и ответов: всё, кроме JSON-ответа (который обязан быть CursedJSON),
остаётся на усмотрению программиста.

## 2. Virtual-объект (псевдообъект)

Не имеет ограничений в ответе и в запросе. Только если ответ идёт в JSON - он должен идти в CursedJSON.

Примеры:

```
GET  /v1/stats
POST /v1/auth/login
GET  /v1/health
```

## 3. Служебные пути

| Путь | Назначение |
|------|------------|
| `/v1/health` | Проверка живости сервиса (обычно без авторизации) |
| `/v1/version` | Версия API и список поддерживаемых версий |
| `/v1/docs` | Документация (OpenAPI/Swagger или своя) |

## Версионирование

Версия указывается в начале пути: `/v1/...`, `/v2/...`. Ломающие изменения - новая версия. Обратно несовместимые версии живут параллельно.
